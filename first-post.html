Getting a feel for A/B test power analysis

Every time I run a small experiment, I want to believe the result the moment I see it. The truth is that with a small sample, a "40% lift" can be indistinguishable from noise. Below are a couple of cells you can actually run and tweak — edit the code, hit run, and see how the numbers move.

1. A quick simulation in JavaScript

This cell simulates flipping two biased coins (control vs. variant) many times and reports how often the variant "wins" purely by luck when the true rates are actually equal. Try changing trials or the sample size and re-running.

In [1]:

function simulate(sampleSize, trials) {
  let falseWins = 0;
  for (let t = 0; t < trials; t++) {
    let a = 0, b = 0;
    for (let i = 0; i < sampleSize; i++) {
      if (Math.random() < 0.10) a++; // control, true rate 10%
      if (Math.random() < 0.10) b++; // variant, ALSO true rate 10%
    }
    if (b > a) falseWins++;
  }
  return (falseWins / trials * 100).toFixed(1) + '% of trials showed variant "winning" by chance';
}

console.log(simulate(200, 2000));

2. The actual power calculation, in Python

        

          Same question, done properly: given a baseline conversion rate and
          a minimum lift worth detecting, how many users do you need per arm?

import math

def required_sample_size(p1, mde, alpha=0.05, power=0.8):
    p2 = p1 + mde
    z_alpha = 1.96   # two-sided, alpha = 0.05
    z_beta = 0.84    # power = 0.80
    pooled = (p1 + p2) / 2
    numerator = (z_alpha * math.sqrt(2 * pooled * (1 - pooled))
                 + z_beta * math.sqrt(p1*(1-p1) + p2*(1-p2))) ** 2
    return math.ceil(numerator / (mde ** 2))

n = required_sample_size(p1=0.10, mde=0.02)
print(f"Users needed per arm to reliably detect a 2pt lift: {n}")
